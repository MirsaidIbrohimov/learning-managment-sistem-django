inPAY API v2

inPAY API v2 orqali saytingiz, ilovangiz yoki Telegram botingizda to'lov qabul qilasiz: to'lov yaratasiz, xaridorni tayyor to'lov sahifasiga yuborasiz va natijani webhook orqali olasiz.

To'lov qanday o'tadi

  1. To'lov yarating — serveringizdan POST /payments/.
  2. Xaridorni yo'naltiring — javobdagi checkout_url manziliga. U yerda xaridor Click, Payme yoki karta bilan to'laydi.
  3. Natijani oling — inPAY serveringizga imzolangan payment.succeeded webhook yuboradi.
  4. Tekshiring — xohlasangiz GET /payments/{id} bilan holatni qayta so'rang.

Umumiy qoidalar

  • Asosiy manzil: https://inpay.uz/api/v2
  • So'rov va javoblar JSON formatida, UTF-8.
  • Summalar so'mda, butun son (50000 = 50 000 so'm). Eng kam summa — 1 000 so'm.
  • Vaqt maydonlari — Unix vaqt belgisi (soniyalarda).

Autentifikatsiya

Har bir so'rovda maxfiy kalitni Authorization sarlavhasida yuboring. Kalitlar kabinetda: Kassa → API v2 kalitlari.

KalitVazifasi
sk_test_…Sinov rejimi. Haqiqiy pul yechilmaydi.
sk_live_…Jonli rejim. Haqiqiy to'lovlar.
  • Kalit faqat yaratilgan paytda bir marta to'liq ko'rsatiladi — bizda uning nusxasi saqlanmaydi. Yo'qotsangiz, kabinetda «Yangilash» orqali yangisini oling (eskisi darhol ishlamay qoladi).
  • Kalitni faqat serverda saqlang. Brauzer yoki mobil ilova kodiga qo'ymang.
  • API v1 kaliti v2'da ishlamaydi.
  • Kassada IP cheklovi yoqilgan bo'lsa, so'rov faqat ruxsat etilgan IP manzillardan qabul qilinadi.

Sinov rejimi

sk_test_ kaliti bilan yaratilgan hamma narsa sinov rejimida ishlaydi: haqiqiy pul yechilmaydi, javoblarda livemode: false bo'ladi.

Sinov to'lovining checkout_url manzili haqiqiy to'lov sahifasi o'rniga simulyatorni ochadi. Quyidagi test kartalaridan birini kiriting:

Karta raqamiNatija
8600 0000 0000 0001succeeded to'lov o'tadi
8600 0000 0000 0002failed insufficient_funds — mablag' yetarli emas
8600 0000 0000 0003failed expired_card — karta muddati o'tgan
8600 0000 0000 0004failed invalid_cvv
8600 0000 0000 0005requires_action qo'shimcha tasdiq kutiladi
8600 0000 0000 0006failed processing_error

Sinov rejimida webhook'lar ham yuboriladi (livemode: false), shuning uchun butun oqimni jonliga chiqishdan oldin sinab ko'rishingiz mumkin. Jonli rejimga o'tish uchun kalitni sk_live_ ga almashtirish kifoya.

Idempotency-Key

Tarmoq uzilib, javob kelmay qolsa, so'rovni qayta yuborasiz — va ikkita to'lov yaratilib qolishi mumkin. Buning oldini olish uchun POST so'rovlarda Idempotency-Key sarlavhasini yuboring (masalan, buyurtma raqamingiz yoki UUID).

  • Bir xil kalit + bir xil mazmun → avvalgi javob qaytadi, yangi to'lov yaratilmaydi.
  • Bir xil kalit + boshqa mazmun → 409 idempotency_key_reused.
  • Bir xil kalitli ikki so'rov bir vaqtda kelsa, ikkinchisi birinchisi tugashini kutadi.
  • Kalit 24 soat saqlanadi; 1–128 ta bosma belgi.
Kalit boshqa mazmun bilan ishlatilganda 409
{
    "success": false,
    "error": {
        "type": "invalid_request_error",
        "code": "idempotency_key_reused",
        "message": "Bu Idempotency-Key boshqa mazmundagi so'rov uchun ishlatilgan. Yangi so'rov uchun yangi kalit yuboring.",
        "request_id": "req_7f67b0b37924",
        "param": "Idempotency-Key"
    }
}

To'lovlar

To'lov — xaridordan pul olishga bitta urinish. Yaratilgach, xaridorni checkout_url ga yuborasiz.

POSThttps://inpay.uz/api/v2/payments/

Yangi to'lov yaratadi va to'lov sahifasi manzilini qaytaradi. Xaridorni checkout_url ga yo'naltiring.

Idempotency-Key yuborish tavsiya etiladi.

To'lov holatlari

HolatMa'nosi
requires_payment_methodYaratilgan, xaridor hali to'lamagan.
requires_actionXaridordan qo'shimcha tasdiq kutilmoqda.
processingTo'lov tizimi javobi kutilmoqda.

Buyurtmani faqat succeeded holatida — webhook yoki GET /payments/{id} javobiga qarab — bajarilgan deb hisoblang. Xaridor return_url ga qaytgani to'lov o'tganini anglatmaydi.

Payment Intents

Xaridor saytingizdan chiqib ketmasdan to'lashi uchun: serverda PaymentIntent yaratasiz, client_secret ni brauzerga berasiz, inpay.js esa to'lov oynasini ochib, natijani kuzatib turadi. Ichkarida PaymentIntent — oddiy to'lovning o'zi: bir xil tekshiruvlar, bir xil webhook'lar.

Qanday ishlaydi

  1. Serverda maxfiy kalit bilan PaymentIntent yarating va javobdagi client_secret ni sahifangizga uzating.
  2. Brauzerda xaridor «To'lash» tugmasini bosganda InPay.confirmPayment() ni chaqiring — inPAY to'lov sahifasi alohida oynada ochiladi.
  3. Xaridor to'laydi; kutubxona holatni kuzatadi va to'lov o'tgach Promise bajariladi — sahifangiz yangilanmasdan «rahmat» ko'rsatasiz.
  4. Serverda buyurtmani payment.succeeded webhook'i kelganda bajaring.
  • client_secret maxfiy kalit emas: u bilan faqat shu bitta to'lovning holatini o'qish mumkin. Uni brauzerga berish xavfsiz.
  • Karta ma'lumoti sizning saytingizga tegmaydi — xaridor uni inPAY sahifasida kiritadi.
  • Brauzerdagi natija faqat ko'rsatish uchun. Tovar berish qarorini webhook yoki serverdagi GET /payment_intents/{id} javobiga qarab qiling.
  • Oyna bloklansa (brauzer sozlamasi), kutubxona xaridorni to'lov sahifasiga to'liq yo'naltiradi; return_url ko'rsatilgan bo'lsa, to'lovdan keyin o'sha manzilga qaytadi.

Imzoni tekshirish

Har bir xabar kassangizning maxfiy siri bilan imzolanadi. Imzoni tekshirmasdan xabarga ishonmang — aks holda istalgan odam serveringizga soxta «to'landi» xabarini yubora oladi.

  1. X-Inpay-Signature sarlavhasidan t (vaqt) va v1 (imzo) ni ajrating.
  2. Vaqt 5 daqiqadan eski bo'lsa — rad eting.
  3. HMAC-SHA256("{t}.{xom tana}", sir) ni hisoblang.
  4. Natijani v1 bilan doimiy vaqtli taqqoslash orqali solishtiring.

Imzo so'rovning xom tanasi bo'yicha hisoblanadi. Tanani avval JSON'ga aylantirib, qayta satrga o'girsangiz, imzo mos kelmaydi.

Tekshirish namunasi

    http_response_code(400); exit('Imzo sarlavhasi topilmadi');

def inpay_webhook():
    payload = request.get_data()          # xom tana, o'zgartirilmagan
    m = re.match(r"t=(\d+),v1=([a-f0-9]+)", request.headers.get("X-Inpay-Signature", ""))
    if not m:
        return "Imzo sarlavhasi topilmadi", 400
    timestamp, signature = m.groups()
    if abs(time.time() - int(timestamp)) > 300:
        return "So'rov vaqti eskirgan", 400

    expected = hmac.new(SECRET, f"{timestamp}.".encode() + payload, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, signature):
        return "Imzo noto'g'ri", 401

    event = json.loads(payload)

  const m = /t=(\d+),v1=([a-f0-9]+)/.exec(req.get('X-Inpay-Signature') || '');
  if (!m) return res.status(400).send('Imzo sarlavhasi topilmadi');
  const [, timestamp, signature] = m;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) {
    return res.status(400).send("So'rov vaqti eskirgan");
  }

  const expected = crypto.createHmac('sha256', SECRET)
    .update(`${timestamp}.`).update(req.body).digest('hex');
  const ok = expected.length === signature.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));
  if (!ok) return res.status(401).send("Imzo noto'g'ri");

  const event = JSON.parse(req.body.toString());
  if (event.type === 'payment.succeeded') {
    const payment = event.data.object;
    // buyurtmani to'langan deb belgilang
  }
  res.json({ received: true });
});
